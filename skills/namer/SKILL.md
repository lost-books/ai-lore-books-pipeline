# Namer Skill

## Purpose

Generate names that belong to the manuscript's world rather than defaulting to a generic genre naming distribution.

Use this skill for:

- characters
- families and dynasties
- settlements
- kingdoms, states, regions, and territories
- geographic features
- institutions and organizations
- religions and deities
- artifacts, vessels, weapons, technologies, and other named objects
- historical events, eras, or movements when a proper name is required

Use this skill whenever manuscript generation requires a new proper name.

## Core Principle

Treat names as outputs of naming systems, not as isolated creative choices.

Do not generate names primarily by selecting forms that merely "sound like fantasy," "sound historical," "sound futuristic," or otherwise match a broad genre stereotype.

Infer the manuscript-specific naming distribution first.

The goal is contextual plausibility without falling back to highly learned generic naming patterns.

## First Question: Does This Entity Need a Name?

Do not invent a proper name merely because one could be supplied.

Before generating a name, determine whether naming the entity serves a narrative, worldbuilding, continuity, or clarity function.

Incidental figures such as guards, clerks, servants, bartenders, messengers, neighbors, or passing officials may remain unnamed when naming them adds nothing.

Likewise, do not automatically name minor roads, institutions, artifacts, geographic features, or historical events.

If no name is needed, return that no new proper name should be introduced.

## Existing Names Are Evidence

Before generating a new name, inspect relevant existing names in the manuscript.

Use them as evidence for:

- phonology
- morphology
- syllable structure
- stress patterns
- consonant clusters
- vowel patterns
- recurring stems
- prefixes and suffixes
- grammatical markers
- family-name conventions
- titles and honorifics
- patronymic or matronymic systems
- geographic naming conventions
- class differences
- regional differences
- religious influence
- historical influence
- migration
- conquest
- colonization
- linguistic contact
- transliteration
- orthography
- register

Do not assume all existing names belong to one system.

Identify whether multiple naming systems are present before generating anything new.

## Identify the Relevant Naming System

Determine which naming system the new entity belongs to.

Possible distinctions include:

- language
- culture
- region
- historical period
- religion
- social class
- political affiliation
- colonial history
- diaspora
- species or nonhuman culture
- institutional tradition
- technological culture
- family or dynasty

Generate within the relevant system instead of averaging together all names in the manuscript.

## When No Relevant Existing Names Exist

If the manuscript provides no relevant existing names, do not default to generic genre-coded naming.

Instead, infer the naming environment from non-name evidence already present in the manuscript.

Relevant evidence may include:

- geography
- climate
- settlement history
- political structure
- historical influences
- religion
- technology level
- social organization
- real-world cultural analogues, if any
- language cues in dialogue
- titles
- terminology
- legal or administrative language
- architecture
- trade networks
- migration
- conquest
- colonization
- neighboring cultures

Determine whether the available evidence supports:

- a real-world naming tradition
- a modified real-world tradition
- an invented naming system
- ordinary contemporary names
- several interacting naming systems

If enough evidence exists, derive a provisional naming system from it.

If evidence remains weak, prefer low-ornament and structurally ordinary names over strongly genre-coded inventions.

Do not introduce a highly distinctive naming style merely to make the setting feel fantastical.

Treat the first invented names as provisional anchors rather than definitive templates.

Do not allow the first arbitrary name to determine the phonology or morphology of every later name.

Once several names exist, reassess them collectively for accidental clustering.

## Feature-Bundle Analysis

Evaluate proposed names as combinations of features rather than as isolated strings.

Relevant features include:

- opening consonants or vowels
- recurring stems
- suffixes
- syllable count
- syllable rhythm
- vowel density
- consonant density
- consonant clusters
- terminal sounds
- stress placement
- morphological structure
- semantic transparency
- degree of ornamentation
- linguistic resemblance
- mythological resemblance
- use of archaic-looking forms
- use of English compounds
- unusual punctuation
- apostrophes
- hyphens
- accents
- unusual capitalization

The question is not only whether a name is individually plausible.

Also ask what feature bundle it contributes to the manuscript as a whole.

## Avoid Generic Genre Defaults

Reject candidates whose plausibility depends mainly on familiar genre-coded patterns rather than manuscript evidence.

Common default mechanisms include:

- vowel-heavy invented stems
- soft consonant patterns used primarily to make a name sound elegant
- pseudo-Celtic morphology
- pseudo-Latinate morphology
- pseudo-Norse morphology
- interchangeable medieval-European forms
- ornamental suffixes
- repeated `ae`, `ia`, `ora`, `aris`, `ion`, `ara`, and similar sound patterns
- invented names built mainly from familiar fantasy phonemes
- place names built from generic evocative compounds
- repeated use of atmospheric or symbolic nouns such as shadow, silver, raven, storm, frost, moon, star, ember, vale, mere, fall, reach, hold, keep, haven, or spire
- names whose main function appears to be signalling that the setting is fantastical

These forms are not prohibited.

Use them when the manuscript's own naming logic supports them.

Do not use them merely because they are genre-compatible.

## Cross-Category Coupling

Evaluate names across entity categories, not only within the same category.

Compare a new name against:

- personal names
- family names
- dynasties
- settlements
- kingdoms
- regions
- rivers
- mountains
- institutions
- religions
- gods
- artifacts
- vessels
- historical periods
- other named entities

Watch for accidental convergence across categories.

A character name, kingdom name, river name, and deity name may each seem individually acceptable while collectively revealing the same generic feature bundle.

Check for:

- phonological coupling
- morphological coupling
- semantic coupling
- register coupling
- cultural coupling

Do not assume similarity automatically creates coherence.

Cross-category similarity should have an in-world explanation.

Possible explanations include:

- shared language
- common ancestry
- political inheritance
- dynastic influence
- religion
- colonization
- conquest
- migration
- commemorative naming
- historical renaming
- geographic naming tradition
- shared administrative language

Where no such relationship exists, preserve meaningful distinctions between naming systems.

## Generation Drift

Do not allow recently invented names to become automatic templates for subsequent names.

A generated name can condition later outputs toward nearby forms.

Before generating another name, compare against the broader manuscript evidence rather than simply continuing the pattern established by the most recent invention.

Avoid chains in which one invented form produces increasingly similar later forms unless the manuscript explicitly supports the derivational relationship.

The naming system should emerge from world evidence, not from model momentum.

## Distinctiveness

Names should be distinguishable without being artificially exotic.

Check important nearby names for:

- same initial
- similar length
- similar syllable count
- similar stress
- similar vowel sequence
- similar consonant skeleton
- similar visual shape
- similar suffixes
- likely reader confusion

Do not solve similarity by making every new name more ornate.

Use structural differentiation where possible.

## Real-World Linguistic Influence

When the manuscript clearly draws from a real language or naming tradition, preserve that influence with enough consistency to maintain plausibility.

Do not randomly combine fragments from unrelated languages merely because they sound compatible.

If the manuscript uses a fictionalized or altered version of a real naming tradition, infer the transformation rules already present rather than reverting directly to the source culture.

Do not flatten culturally distinct naming systems into one generic fantasy register.

## Semantic Naming

Do not automatically make names reflect:

- personality
- powers
- morality
- appearance
- destiny
- narrative role
- thematic symbolism

A fire-associated character does not inherently need a fire-associated name.

A villain does not inherently need a harsh-sounding name.

A mountain kingdom does not inherently need a name containing stone, iron, frost, peak, or similar imagery.

Use semantic naming only where the manuscript establishes such a convention.

## Personal Names

For personal names, consider:

- generation
- region
- family
- class
- religion
- culture
- formal versus familiar form
- inherited names
- nicknames
- patronymics
- matronymics
- married names
- regnal names
- aliases

Do not give every important character an ornamental or unusually distinctive name.

Ordinary names may be more appropriate.

## Place Names

Treat place names as historical artifacts rather than decorative labels.

Consider:

- who named the place
- what language they spoke
- whether the name predates the current population
- whether conquest changed the name
- whether outsiders use a different name
- whether the name derives from geography
- whether it derives from a person
- whether it preserves an obsolete word
- whether spelling changed over time
- whether administrative renaming occurred
- whether the current form is a translation or corruption of an older form

Do not default to generic compound place names merely because they are immediately legible.

## Institutions and Organizations

Institutional names should reflect the language, political culture, and historical circumstances that created them.

Avoid defaulting automatically to grandiose constructions such as:

- The Order of...
- The Council of...
- The Brotherhood of...
- The Keepers of...
- The Circle of...

Use such forms only when the manuscript supports that register.

## Existing Names Are Facts

Never rename an existing entity unless explicitly instructed.

Preserve:

- spelling
- capitalization
- punctuation
- diacritics
- spacing
- titles
- aliases
- established short forms

Do not silently "correct," simplify, modernize, or improve unusual existing names.

## Candidate Generation

When a new name is required:

1. Identify the entity type.
2. Determine whether the entity actually needs a name.
3. Identify the relevant naming system.
4. Gather relevant manuscript evidence.
5. If name evidence is absent, gather broader cultural, linguistic, geographic, historical, and social evidence.
6. Infer feature constraints.
7. Generate several internal candidates.
8. Compare candidates against relevant existing names.
9. Compare candidates across entity categories.
10. Remove candidates that depend mainly on generic genre-coded feature bundles.
11. Remove candidates that create excessive feature concentration.
12. Remove candidates that overfit recently generated names.
13. Remove candidates likely to confuse readers because of similarity to existing important names.
14. Prefer the candidate best supported by manuscript-specific evidence.
15. Recheck the selected name as part of the manuscript's larger naming system.

Do not expose internal candidate lists unless explicitly requested.

## Evaluation Test

Before finalizing a new name, evaluate:

- Does the entity need a name?
- What naming system does it belong to?
- What manuscript evidence supports the name?
- If no prior names exist, what non-name evidence supports the naming system?
- Does the name rely mainly on a generic genre feature bundle?
- Does it reinforce an already concentrated phonological or morphological pattern?
- Does it create cross-category coupling without an in-world reason?
- Does it imitate recently generated names?
- Is it confusingly similar to an existing important name?
- Is it more ornamental than surrounding names?
- Does it introduce a naming style that would unnecessarily constrain later worldbuilding?
- Would a simpler or more ordinary name fit better?

Reject a candidate if the main reason it works is merely that it sounds appropriate for the genre.

## Blacklists

Do not use a blacklist as the primary naming mechanism.

A blacklist may exist only as a secondary guardrail against especially persistent default outputs.

The presence or absence of a name on a blacklist does not determine whether the name is appropriate.

Manuscript-specific evidence and feature-bundle analysis take precedence.

Do not solve naming problems by continually expanding the blacklist.

## Output

When called by another manuscript skill, return:

- selected name
- entity type
- naming system or cultural context used
- optional short rationale when metadata is requested

When writing directly into manuscript prose, normally output only the name in context.

Do not expose naming analysis unless requested.

## Final Rule

The goal is not to invent a name that sounds appropriate for the genre.

The goal is to produce a name that appears to have emerged from the manuscript's own history, language, culture, social structure, and naming conventions.

When those systems are not yet established, preserve optionality rather than allowing generic genre defaults to establish them accidentally.
